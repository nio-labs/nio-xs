One clear boundary: the caller owns tools and permissions. NioXS can request an advertised action; the caller decides whether and how to execute it.

2. Quickstart

Install

On Linux, macOS, or Termux:

curl -fsSL https://raw.githubusercontent.com/nio-labs/nio-xs/main/install.sh | bash

Or run with Docker:

docker run -d --name nioxs -p 7460:7460 ghcr.io/nio-labs/nioxs:latest

Connect your agent

Start NioXS and point an OpenAI-compatible client at the local endpoint. Choose nio-flow for the orchestrated profile.

nioxs init
# API base URL: http://127.0.0.1:7460/v1
# Model ID:     nio-flow

For Aider:

aider --openai-api-base http://127.0.0.1:7460/v1 \
  --openai-api-key none --model nio-flow
The NioXS API follows the OpenAI chat-completions shape at /v1/chat/completions. The available Nio profiles are listed by /v1/models.

Each profile has a distinct job. Choose one directly from your client's model picker, or let NioFlow select useful roles for the task.

Profiles share configured upstream models and Rust workflows. They are not separate hosted model weights.

4. How NioFlow routes work

  1. Plan: NioFlow reads the prompt and available tools, then prepares a bounded plan.
  2. Gather context when needed: Nano can request a native file listing when the answer depends on this project and the caller offers the file tool. If that optional step fails, Flow continues with available evidence and reports the limitation.
  3. Hand off by task: Flow invokes useful answer, teaching, writing, research, reflection, exploration, implementation, or review roles. Status lines show the selected role and upstream model changes.
  4. Decide last: Helm provides the final Go / No-Go by default. Use --no-helm to skip Helm for one Flow task. Direct selection of other profiles does not add a Helm stage.

Upstream model path

NioFlow starts with Kilo North Mini Code. If it is unavailable, Flow falls back to Kilo Auto Free. When the task has multiple concrete signs of complexity, Flow checks the live Kilo /models catalog and may switch to a free StepFun model that advertises tool support. If StepFun is unavailable, Flow falls back to Auto Free. Explicit model settings are respected.

🌊 NioFlow · Planning
↪ NioAtom · Building
↪ Upstream: cohere/north-mini-code:free → stepfun/<catalog model> (high task complexity)
⚖ NioHelm · Go / No-Go

General questions, explanations, and feasibility requests do not trigger workspace scans. The caller persona remains active across plans, handoffs, and final answers.

6. Tools, privacy & permissions

  • NioXS only relays tools advertised by the caller. The calling agent remains responsible for project access, approvals, and execution.
  • Model output, repository files, tool results, and fetched web content are treated as untrusted input.
  • Flow bounds its stages and tool rounds, carries results across handoffs, and avoids replaying completed actions.
  • StepFun escalation is conditional on task evidence and the live model catalog; it does not override an explicit upstream model choice.
  • Kilo free models may be served by trial providers under their own terms. Review Kilo's free-model guidance before sending sensitive data.
Helm's Go is a readiness assessment against the evidence and criteria. It does not grant tool permission or replace the caller's approval.

8. FAQ

Are NioFlow, NioAtom, and the other profiles separate models?

They are role profiles and Rust-controlled workflows that share the configured upstream model. NioNano has a local MicroLM component.

Will a general question read my project files?

No. NioFlow routes general questions directly and only asks for project evidence when the task depends on the current project.

Does NioHelm approve changes?

Helm reports Go, Conditional Go, or No-Go from evidence. The calling agent still enforces its approval policy before a tool runs.

Can I use NioThinker without Helm?

Yes. Direct Thinker runs its bounded three phases without Helm by default. Add --with-helm when you want a final decision.
