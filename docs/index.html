3. Connect Your Coding Agents (`nioxs init`)

NioXS exposes a standard OpenAI-compatible completions endpoint on http://127.0.0.1:7460/v1. You can auto-configure your current workspace or select your editor below:

# Auto-detect and configure all agents in the current project
nioxs init

Run Aider directly against NioFlow, or write an .aider.conf.yml file:

aider --openai-api-base http://127.0.0.1:7460/v1 --openai-api-key none --model nio-flow

Or in .aider.conf.yml:

openai-api-base: http://127.0.0.1:7460/v1
openai-api-key: none
model: openai/nio-flow

In Cursor: Navigate to Settings ➔ Models ➔ OpenAI API Key:

  1. Enable Override OpenAI Base URL and enter: http://127.0.0.1:7460/v1
  2. Enter any dummy key (e.g. none) if NIOXS_ALLOW_UNAUTHENTICATED=true, or your NIOXS_API_TOKEN.
  3. Add Model Name: nio-flow.

In Cline or Roo Code, select OpenAI Compatible provider in settings, or configure cline_mcp_settings.json:

{
  "apiProvider": "openai",
  "openAiBaseUrl": "http://127.0.0.1:7460/v1",
  "openAiApiKey": "none",
  "openAiModelId": "nio-flow"
}

Auto-generate opencode.json using nioxs init --opencode or save:

{
  "model": "nio-flow",
  "apiBase": "http://127.0.0.1:7460/v1",
  "apiKey": "none"
}

Add NioXS to your ~/.continue/config.json under the models array:

{
  "title": "NioXS (NioFlow)",
  "provider": "openai",
  "model": "nio-flow",
  "apiBase": "http://127.0.0.1:7460/v1",
  "apiKey": "none"
}

6. NioNano: MicroLM (Micro Learning Model)

NioNano is the core differentiator in AXIS. While large foundation models (LLMs) require gigabytes of VRAM, introduce latency, and risk hallucination, NioNano is a 46 KB deterministic learning model running natively inside the compiled Rust binary. It executes sub-millisecond local intent classification, verified evidence collection, compiler diagnostic triage, and anti-hallucination guardrails right in your developer terminal or TUI companion.

Key Distinction: Decision Modeling, Not Generative Text
NioNano does not hallucinate free-form text or attempt to write entire features from scratch. Instead, it turns natural language into typed, verifiable intents, selects bounded local workflows and installed plugins, and feeds verified ground truth to upstream models. The LLM remains the reasoning and authoring partner; NioNano owns routing, policy, evidence, and execution.

Taxonomy: What makes it a MicroLM?

46 KB Footprint

Embedded directly into the single binary (models/nano.json). Zero Python runtime or heavy model weights required for core decision loops.

<0.5ms Inference

Pure CPU-native computation with zero GPU or VRAM requirements. Evaluates feature weights and class priors in a fraction of a millisecond.

Deterministic Guard

Calibrated Bayesian thresholds fail closed on ambiguity, ensuring commands and code modifications only proceed when grounded in project reality.

Under the Hood: The Bayesian Engine

NioNano implements a trained Multinomial Naive Bayes classifier operating on tokenized n-grams and calibrated priors. Each incoming developer prompt is scored across 7 primary intent classes:

Intent LabelConfidence RuleAction Triggered
read_fileHigh prob + path tokenExtracts file slices and passes contents to agent context.
inspect_projectHigh prob + project scopeScans workspace structure and active language manifests.
find_filesPattern match + globExecutes fast, bounded directory searches without LLM token cost.
search_codeSymbol / regex tokenScans project symbols and AST references.
run_checksBuild / test triggerRuns detected build pipelines (cargo test, npm test, pytest, go test).
clarifyBelow margin thresholdPrompts the caller for missing parameters instead of guessing.
unsupportedFails safety / policyRejects unsafe requests cleanly before upstream routing.

Core Responsibilities in the AXIS Pipeline

  1. Instant Intent & Directive Triage: When you type a command or directive (such as --bash, --test, --git, or --tools), NioNano parses and dispatches the action immediately in-session without waiting for an upstream cloud model round-trip.
  2. Anti-Hallucination & Reality Check (--code! / --code guard): Upstream generative models often invent nonexistent files or ghost API symbols. NioNano validates code proposals against local AST symbol trees across Rust, TypeScript, Python, and Go before writing diffs or executing mutations.
  3. Native Autonomous Web & Source Research: When investigating libraries or errors, NioNano coordinates native, headless research against DuckDuckGo Lite, Wikipedia, and GitHub using a pure-Rust BM25 lexical ranker—requiring zero external browser dependencies or search API keys. Excerpts are cached in NioDB with durable cryptographic evidence.
  4. Bounded Flow Continuation: During multi-step NioFlow tasks, NioNano carries forward collected evidence, file contents, and check results across specialist handoffs (Nova, Atom, Neon, Helm), invalidating stale caches whenever local mutations occur.

7. How NioFlow Routes Work

Every turn processed by NioXS passes through an end-to-end, bounded lifecycle flow:

1

Prompt Arrival & MicroLM Triage

NioNano evaluates incoming input in <0.5ms. Directives (e.g. --bash, --test) execute locally without touching cloud models. General queries bypass project file scans.

2

Bounded Task Planning (`NioFlow`)

Flow maps the objective into focused specialist roles. It preserves caller context and pins active turn constraints across handoffs.

3

Specialist Execution (`Atom` / `Neon` / `Scout`)

Specialists generate patches (AtomContract), audit code changes (NeonReviewContract), or fetch documentation with BM25 lexical ranking.

4

Anti-Hallucination AST Guard

Candidate modifications are checked against actual AST symbols in Rust, TypeScript, Python, and Go, refusing non-existent paths.

5

Final Evidence Gate (`NioHelm`)

Helm evaluates the gathered evidence and returns an authoritative Go, Conditional Go, or No-Go verdict before relaying results to the caller.

6

Cryptographic State Journal (`NioDB`)

Actions, turns, and evidence digests are immutably persisted in NioDB, enabling state rollback (nioxs undo) and audit histories (nioxs history).

Upstream Model Path

NioFlow starts with Kilo North Mini Code. If it is unavailable, Flow falls back to Kilo Auto Free. When the task has multiple concrete signs of complexity, Flow checks the live Kilo /models catalog and can escalate to a free StepFun model that advertises tool support.

NioFlow · Planning
↪ NioAtom · Building
↪ Upstream: cohere/north-mini-code:free → stepfun/<catalog model> (high task complexity)
⚖ NioHelm · Go / No-Go

10. Python Tool Plugins Ecosystem (`--tools`)

NioXS supports dropping modular Python plugins into ~/.nioxs/plugins/ to extend coding agent capabilities with zero server recompilation.

How Plugins Work

  1. Create a .py file in ~/.nioxs/plugins/my_plugin.py.
  2. Define a top-level def run(prompt: str) -> str function.
  3. NioNano detects the plugin and advertises it to calling agents and MCP.
  4. Before executing any newly installed or downloaded plugin, NioXS prompts the developer for explicit consent.

Example Plugin

# ~/.nioxs/plugins/extract_colors.py
import re, json

def run(prompt: str) -> str:
    """Extracts hex color codes from text or CSS strings."""
    hex_colors = re.findall(r'#(?:[0-9a-fA-F]{3}){1,2}\b', prompt)
    return json.dumps({"colors": list(set(hex_colors))})

11. Tools, Privacy & Permissions

  • NioXS only relays tools advertised by the caller. The calling agent remains responsible for project access, approvals, and execution.
  • Model output, repository files, tool results, and fetched web content are treated as untrusted input.
  • Flow bounds its stages and tool rounds, carries results across handoffs, and avoids replaying completed actions.
  • StepFun escalation is conditional on task evidence and the live model catalog; it does not override an explicit upstream model choice.
  • Kilo free models may be served by trial providers under their own terms. Review Kilo's free-model guidance before sending sensitive data.
Helm's Go is a readiness assessment against the evidence and criteria. It does not grant tool permission or replace the caller's approval.

13. FAQ

Are NioFlow, NioAtom, and the other profiles separate models?

They are role profiles and Rust-controlled workflows that share the configured upstream model. NioNano has a local MicroLM component.

Will a general question read my project files?

No. NioFlow routes general questions directly and only asks for project evidence when the task depends on the current project.

Does NioHelm approve changes?

Helm reports Go, Conditional Go, or No-Go from evidence. The calling agent still enforces its approval policy before a tool runs.

Can I use NioThinker without Helm?

Yes. Direct Thinker runs its bounded three phases without Helm by default. Add --with-helm when you want a final decision.

How does NioXS compare to a traditional reverse proxy?

Unlike raw proxies, NioXS embeds NioNano (<0.5ms intent triage), Anti-Hallucination AST symbol validation, native web research, and cryptographic action logging in NioDB.
